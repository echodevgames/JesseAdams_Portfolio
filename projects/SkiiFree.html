SkiiFree ’26 — Classic Remake & Gameplay Systems

A solo remake of the classic 1991 SkiFree, rebuilt with modern gameplay architecture while preserving the original’s fast, readable design. " I handled all systems programming, game logic, and pixel art creation.

Project Overview

SkiiFree ’26 is a faithful reinterpretation of the original SkiFree, focusing on deterministic movement, escalating challenge, and instantly readable player feedback.

The goal was not to modernize the game into something unrecognizable, but to understand what made the original work — and rebuild it using clean, maintainable systems.

  • Solo Project
  • Classic Game Remake
  • Gameplay Systems
  • State-Driven Logic
  • Pixel Art Pipeline

Design Goals

  • Faithful core mechanics
    Preserve the feel, speed, and readability of the original SkiFree.
  • Deterministic gameplay
    Movement, collisions, and enemy behavior are predictable and debuggable.
  • Modern architecture
    Replace legacy assumptions with clear state ownership and system boundaries.
  • End-to-end solo ownership
    Code, art, tuning, and iteration were all handled by a single developer.

Core Gameplay Systems

The game is structured around a central gameplay controller that manages scrolling speed, player state, obstacle interaction, and game-over flow.

  • World scrolling vs player-relative movement
  • Heading-based directional control
  • Obstacle collision & response
  • Score progression and difficulty ramp

Player Movement & Feel

Player movement is intentionally constrained to maintain clarity. Directional changes occur in stepped angles, mirroring the original game’s readable control scheme.

Speed, turning responsiveness, and obstacle reactions were tuned iteratively to preserve the original game’s sense of momentum.

Enemy & Hazard Design

The Yeti acts as a pressure mechanic rather than a traditional enemy. It appears based on elapsed runtime and forces players to maintain forward momentum.

  • Timed spawn logic
  • Relentless forward pursuit
  • Clean kill-state resolution

Game State & Flow

The game uses a simple, explicit state model to control flow:

  • Playing
  • Paused
  • Game Over

Input, UI visibility, and simulation updates are gated by state, preventing edge cases and unintended transitions.

Art Pipeline & Visual Design

All art assets were created by hand using Aseprite. The visual goal was clarity first — silhouettes, contrast, and animation readability over decorative detail.

  • Custom skier animations
  • Obstacle sprites & tiles
  • Enemy sprites
  • UI and HUD elements

What I Learned

  • Classic design holds up
    Many older games work because of clarity and restraint, not complexity.
  • Feel comes from tuning
    Small parameter changes dramatically affect player perception.
  • Solo projects expose every weakness
    Architecture, art workflow, and iteration speed all matter when there’s no one else to absorb mistakes.
